Прямой доступ на 8080 vs reverse proxy через nginx
Если просто открыть 8080 наружу , «сайт работает», но теряются как минимум две важные возможности, которые даёт reverse proxy :
1 Теряется централизованный TLS/SSLNginx на 80/443 берёт на себя SSL-терминацию: он говорит с клиентом по HTTPS, а с backend-ом — по обычному HTTP. В варианте (а):Либо пользователи ходят по открытому HTTP на порт 8080 (пароли, куки, сессии — всё в открытом виде).Либо нужно настраивать TLS внутри каждого приложения отдельно, выдавать сертификаты каждому, перезагружать каждое при обновлении сертификата.При наличии нескольких сервисов (web-42, ещё какой-нибудь backend, админка) reverse proxy позволяет иметь один сертификат на одном порту 443 и маршрутизировать по имени хоста (Host:) или пути. Без proxy для каждого сервиса нужен свой порт с HTTPS — это и неудобно, и порт 80/443 всего один
2 Теряется единая точка входа и маршрутизация по имени/путиNginx может на одном IP и одном порту 80 размещать сколько угодно сервисов, различая их по:доменному имени или пути URL
